# AGENTS.md

## Repository purpose

This package is Gameflow's manifest-only store. Game entries live as one JSON file per game under `buckets/games/`; `scripts/build-manifests.ts` derives the lightweight catalog and filter indexes under `manifests/`. Keep this file current whenever investigation reveals an essential manifest or runtime constraint.

Changes here affect catalog/manifests only. Download, extraction, task-queue, websocket, and launch behavior is compiled into Gameflow Deck; testing those host changes requires restarting the Deck development backend or rebuilding and launching the Deck executable. Linking this package into Gameflow's managed store does not update host runtime code.

## Game manifest contract

- Use a stable, lowercase, hyphenated filename. Its basename becomes the store game ID and the installed path suffix.
- Validate entries against `schema/game.json`. The required fields are `name`, `homepage`, `version`, and a non-empty `covers` array. `downloads` is necessary for an installable entry even though the JSON schema does not currently require it.
- Prefer an official project or release page for `homepage`. Use direct, durable archive URLs for downloads; landing pages, expiring signed URLs, HTML redirect pages, and hosts that require browser cookies or anti-bot challenges are not reliable store sources.
- An empty `downloads` object is a catalog-only entry and is preferable to a broken or expiring download. Authenticated storefront pages such as GOG product pages are durable acquisition references but are not direct downloads; do not disguise them as `direct` entries.
- A direct download's `system` uses Bun platform and architecture names separated by `:` (for example `win32:x64`). A system without `:` is an emulator/platform slug such as `gba` or `gb`.
- `main` is a Bun glob evaluated inside the extracted game directory. Native desktop entries need a precise launch target because Windows otherwise falls back to the first `**/*.exe`; broad globs can select an installer, updater, crash reporter, or helper. The launcher returns only the first glob match. Direct downloads do not support manifest-supplied command-line arguments or multiple launch choices; a generated platform `launch` wrapper described below is the supported exception for ModDB entries.
- Store archive downloads are extracted, while `additional_files` are preserved as runtime files. ZIP extraction intentionally runs in-process and must be awaited through archive close so installs remain background tasks and completion reaches the UI; reserve the hidden 7-Zip child process for non-ZIP formats. Host task subscribers must register `completed`/`ended` listeners before sending their initial active-job snapshot and remove completed jobs immediately, otherwise extraction can finish in the subscription gap and remain stale until a page refresh. The downloader derives the local filename from the URL basename, so direct archive URLs must end in their real archive filename/extension. Redirect endpoints whose path does not end in `.zip` or `.rar` can break extraction.
- Runtime hooks registered during plugin loading must report work through the operation-specific callback supplied in the hook payload. Never capture the plugin-loading `ctx.setProgress` for later downloads or extraction: that context belongs to the completed reload task, so late progress reopens the global loading screen without a matching completion event.
- Extraction progress belongs to the active install job and must remain in the normal task UI; only plugin reload and self-update jobs may drive Gameflow's global loading screen. When installation completes, the status websocket emits `refresh` with the local game ID, and the frontend must navigate immediately to that local game while cache invalidation runs in the background.
- Native executables are spawned directly. Windows `.bat` and `.cmd` wrappers selected by `main` are invoked through `cmd.exe` with the wrapper path quoted; use a wrapper only when it is part of the upstream release and supplies required launch arguments. Direct downloads do not currently support multiple launch choices or arbitrary manifest-supplied arguments.
- ModDB downloads use `type: "moddb"`, a stable numeric `file_id`, the exact upstream `file_name`, `system`, and optional `main`. Never store a `/downloads/mirror/...` URL: mirror hashes expire. Gameflow resolves `/downloads/start/<file_id>` with browser headers immediately before download. A ModDB `.bat` or `.cmd` wrapper selected by `main` is supported on Windows when the upstream package requires it for launch arguments.
- A ModDB download may include `additional_files` for non-archive runtimes placed in the installed game directory and `launch` for a generated platform wrapper (`.cmd`/`.bat` on Windows or `.sh` on Linux). `launch.wrapper`, `launch.executable`, and optional `launch.cwd` must be relative paths contained by the install directory; `launch.args` is emitted as individually quoted arguments. Optional `launch.bindings` maps controller button names to actions; Gameflow fills missing or empty defaults in `[Doom.Bindings]` without replacing non-empty user bindings. Gameflow preserves additional non-archive files, writes the wrapper after installation, and marks Linux wrappers and runtimes executable.
- Ashes 2063 has no official Linux standalone. Its Linux entry combines the official ModDB data archive with the official UZDoom AppImage; keep the pinned UZDoom version and URL current when updating that bucket. The shipped `gzdoom-ashes.ini` contains gamepad bindings but sets `use_joystick=false`, so both Ashes launch wrappers pass `+use_joystick true`. The manifest also supplies missing `Pad_A=+use` and `Pad_X=+reload` defaults. Gameflow patches the joystick setting, fills only missing or empty bindings, and regenerates the wrapper before play so existing store installs are repaired without overwriting custom controls. Windows has only the archive, so the installer flattens its single `AshesStandalone_V1_51` root and its launch paths begin at `Resources`; Linux also has the AppImage at the install root, so it retains `AshesStandalone_V1_51/Resources`.
- `saves` can be global per `platform:arch` or attached to one download. Each named slot has a `cwd` and `globs`. Supported Mustache roots are `{{{GAMEDIR}}}`, `{{{HOMEDIR}}}`, `{{{TMPDIR}}}`, `{{{APPDATA}}}`, and `{{{LOCALAPPDATA}}}`. `GAMEDIR` is the selected executable's directory, not necessarily the extraction root.
- Covers and screenshots may be package-relative paths or absolute URLs. Prefer a packaged cover under `media/covers/` as the first cover so catalog art remains available offline; include attribution/licensing awareness when importing media.
- Use provider IDs only when verified. `igdb_id`, `ra_id`, and `sgdb_id` are numeric provider IDs, not slugs. Although the repository JSON schema also permits an ISO date, the current runtime SDK accepts `first_release_date` as a Unix timestamp in milliseconds; use the timestamp form until those contracts are aligned.

## Generated manifests and verification

- Do not hand-edit `manifests/games.json` or `manifests/filters.json`; run `bun scripts/build-manifests.ts` after changing a game bucket and inspect the generated contents. The `manifests/` directory is intentionally gitignored, so generated files verify the bucket locally but are not committed.
- Parse every changed JSON file, run the manifest builder, and inspect `git diff --check`. For new direct downloads, verify redirects, response status, content type, archive filename, platform/architecture, extracted launch target, and save locations without downloading large artifacts unnecessarily.
- Host extraction regression coverage must assert that `extract` progress events carry the install job ID rather than a plugin reload job ID; otherwise a completed reload context can reopen an undismissable fullscreen loading screen.
- Keep source facts such as version, supported systems, checksums, archive layout, and launch instructions in sync with the upstream release. A metadata-only validation is not a substitute for an installation and launch test; state when a host or large archive prevented end-to-end verification.

## Change hygiene

- Keep bucket changes focused and avoid unrelated generated churn. Preserve existing user edits.
- Use Bun for project scripts. Use Conventional Commits if asked to commit.
- Never add credentials, authenticated download URLs, cookies, or short-lived signed links to manifests.
